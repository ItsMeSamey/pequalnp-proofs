# Running the prime-power evaluator

[Python source](positive_read_two_prime_power.py) exports evaluate(n, clauses, point, k, *, max_contractions=None). With Python 3.10 or later the same file accepts one JSON object on standard input and the optional flag --max-contractions INTEGER. The four required keys are n, clauses, point and k. For example:

    {"n":1,"clauses":[[0]],"point":[5],"k":2}

This gives status exact, value 5, contractions 3. Indices start at zero and must be smaller than n. The point has exactly n integer success coordinates of arbitrary sign, reduced modulo 3^k. Arity n may be zero and k is positive. Each clause is an array of positive variable indices in the sense of literal polarity; index zero is allowed. Repeated variables each consume a raw occurrence. Each variable has at most two in the complete input. Empty arrays represent empty clauses or an empty conjunction according to position. Python's integral protocol also accepts Boolean values as zero and one.

The default is uncapped. A nonnegative cap limits the exact number of Gaussian contractions for this expansion after Boolean specialization and parallel grouping. An insufficient cap returns status unknown, reason contraction_budget and exact integers required and available, before any contraction. An exact result has fields status, value and contractions, with 0 ≤ value < 3^k. Boolean constant cases identified during normalization use zero contractions. The CLI exits zero for both exact and unknown, and signals invalid data with a nonzero exit. The cap neither bounds polynomial preprocessing nor limits machine memory or elapsed time. The implementation uses the valuation expansion exclusively.

For D=2+k+input bit length (including cap), dictionary/set records of polynomial total length and a stack of admissible indices implement the [proof](positive-read-two-prime-power.md). The preflight dynamic program computes the truncated generating polynomial before testing the cap. It has at most k active degrees and coefficients of O(n) bits. The Gaussian kernel explicitly rebuilds at most O(m²) pairs at a pivot on m clause bits, toggling at most O(m²) pairs. No expected constant-time dictionary assumption is needed for a polynomial multiplier: allowing linear scans of polynomial-sized tables costs polynomial time even in the worst case. The proof's D^8 H_k clock covers an indexed-record multitape implementation. For the source's abstract integer and container operations, allowing a scan of O(D^4) bits per lookup, schoolbook integer arithmetic and polynomial-width index operations gives a conservative O(D^10 (1+H_k)) bit simulation and O(D^4) bits of logical workspace. These are algorithmic bounds without a wall-clock or interpreter-resident memory guarantee. On refusal the H_k loop is skipped and time is polynomial in D. Binary encoding of k does not remove the explicit dependence on its value.

For known fixed-precision counting algorithms, unrestricted-precision hardness on planar incidence instances and the cubic matching variant, see [Precision hardness and prior work](positive-read-two-precision-hardness.md).
