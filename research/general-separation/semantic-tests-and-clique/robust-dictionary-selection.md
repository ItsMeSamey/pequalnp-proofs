# Uniform row sampling for a forced coefficient

In the [selectable dictionary model](selectable-dictionary-quantifiers.md), a pair (y,b) specifies a list of S Boolean features and the equations A(u)c=f(u) on all raw rows, with c_j=b. Validity means consistency. Every input has a valid pair, and all valid pairs have the same bit. A pair is far if every real c satisfying c_j=b disagrees with the target on at least an ε fraction of uniformly sampled rows, for a fixed inverse-polynomial lower bound ε. The wrong-bit promise requires this for every pair with the wrong global bit. The all-invalid-pairs promise requires it for every invalid pair, including an invalid choice accompanied by the correct bit.

## Spot checking and enumerable choices

Start with the equation c_j=b and test consistency as independent row equations arrive. A valid pair always passes. For a far pair, choose any solution to the current consistent system. The next row excludes it with probability at least ε. Such a row strictly lowers the affine dimension or makes the system inconsistent. At most S+1 such events suffice. The expected time to rejection is at most (S+1)/ε rows. A batch twice this size gives error at most 1/2 by Markov's inequality. Independent batches amplify the guarantee. All consistency tests use polynomial-bit exact arithmetic.

For polynomially enumerable choices test both bits for every choice. Reduce each wrong-bit pair's survival probability below the reciprocal of twice the number of choices. An exact pair always survives, and a round eliminates every wrong-bit pair with probability at least 1/2. Repeat with fresh randomness until precisely one bit survives. This is a ZPP algorithm under either promise. Conversely truncate a Las Vegas ZPP decider at twice a polynomial bound on its expected running time. With the uniform random tape as row, define the single feature to indicate that the decider returned an answer, and its label to indicate that it returned YES. The unique coefficient equals the correct bit. The wrong bit violates at least half the rows. Thus polynomially enumerable choices characterize ZPP, already attained with one fixed list of one feature.

## Exponentially many choices

Under the wrong-bit promise the languages are exactly MA ∩ coMA. For either bit, Merlin commits to a polynomial-length choice before Arthur samples. A valid choice passes surely, and all guesses for the wrong bit have bounded acceptance probability. Conversely use perfect-completeness MA verifiers for both sides, amplifying their soundness to at most 1/2. For an index encoding a side s and proof y, let R(z) be the verifier's coin-tape predicate. On uniform rows (t,z) use common target t and features 1−t and tR(z). Designate the first role for s=0 and the second role for s=1. When R always accepts, the role coefficients (0,1) force bit s. Any rejecting tape gives an impossible row at t=1. For a false side, at least half of the tapes reject, yielding distance at least 1/4 for any coefficient vector. A claimed bit different from the encoded side forces either coefficient one on 1−t or coefficient zero on tR, yielding errors on at least half the rows. These cases cover every wrong-bit pair. Perfect completeness for classical MA is due to Zachos and Fürer. [Original theorem](https://doi.org/10.1007/3-540-18625-5_67)

For the all-invalid-pairs promise, let C be the class of languages expressible as ∃y R(x,y), with polynomial-length witnesses and a **total coRP language** R. The exact characterization is C ∩ coC. The fixed-pair sampler recognizes validity of (x,y,b) in coRP. It rejects malformed choice encodings deterministically. Conversely use coRP predicates for witnesses for both sides in the same two-feature construction. Each choice now passes on every tape or fails on a constant fraction of tapes, including false witnesses for the correct side. This gives the stronger gap on all invalid pairs. The characterization is contained in MA ∩ coMA. Ordinary MA completeness constrains one good witness on the true side and does not constrain all the remaining witnesses there.

## Sparse counterexamples and proof checking

For a constant true bit, give the correct side one perfect witness and one witness rejecting just one n-bit coin string. All false-side witnesses always reject. The two-feature system still has constant wrong-bit distance. The imperfect correct-side witness at its own bit has distance exactly 2^{−n−1}. A sample of q rows sees any defective row with probability at most q/2^{n+1}. The [finite checker](robust_choice_sampling_check.py) computes minimum distances for all 256 predicates on eight tapes and every pair of designated role and proposed bit.

A PCP verifier's randomness and number of proof queries impose additional resource bounds. Perfect completeness and soundness for false statements alone do not guarantee that each imperfect proof of a true statement has constant rejection probability. Also, replacing a defect computation by a fully defined gate-trace CNF with v fresh trace bits preserves existence of a defect, but a uniform trace hits its unique correct extension with probability only 2^{−v}. Padding a trace with pinned gates can make this loss arbitrarily large. The circuit-predicate converse above uses the original random tapes. [Arora and Safra, probabilistic checking of proofs](https://www.cs.umd.edu/~gasarch/TOPICS/pcp/AS.pdf)
