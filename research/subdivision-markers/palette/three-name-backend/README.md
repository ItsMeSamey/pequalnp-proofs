# Binary three-name backend

The mathematical specification and input contracts are in ../oracle-contract-audit.md. The Python entry points are exact_line.exact_line for pinned indexed support, first_space.scalar_relation for an original odd relation and compatible support, and first_space.first_space for a realizable basis of L.

For the polynomial recognition branch supply the keyword graphic=partial(is_graphic_cmr, executable=path) using functools.partial and graphic.is_graphic_cmr. The default standalone fallback enumerates trees and is exponential in terminal rank. Resource or process errors propagate from the adapter. The observed pinned executable is /dev/shm/three-name-cmr-src/local/cmr-graphic, SHA256 a9dce47e83cc3e506f7a4423d661a4c341bb63e0372236b4f726e59b407fc361, upstream MIT, revision 0c42a44deb8262a1f2a400add5d6be80e90eda3c. build_cmr.sh reproduces the serial compiler invocation using an existing checkout of that revision containing include/cmr, src/cmr and src/main. CMR's license is in the source checkout. No system installation is required.

Separation discovery implements unweighted matroid intersection on two contractions. For a pair of forced shores, each shortest exchange-graph augmentation grows the common independent set once. The reachable set at termination recovers the minimizing partition. Enumerating independent tuples of up to three on the unrooted shore finds a minimum-order vertical separation. The six padded roots span rank three. Each decomposition strictly decreases rank and adds at most three columns. Gaussian elimination computes the interface in the original ambient without enumerating either shore span. At termination graphicness decides coupling, using the K4 restriction and the graphic recognition criterion after [GGW Theorem 2.1](https://arxiv.org/html/2611.20960v1#S2).

The CMR branch simplifies the explicit representation [I|A] by removing zero and repeated supports and tests A using the documented Bixby–Wagner implementation. The CMR core runs in O(k α(k,m)) on a matrix with m rows and k nonzeros, as documented by [CMR](https://discopt.github.io/cmr/graphic.html). Constructing and writing the dense matrix costs polynomial time in the supplied representation. Polynomial complexity here describes the algorithm with sufficient resources. Tests and integration do not certify a Lean implementation or arbitrary hardware resource bounds.

Independent controls passed for 600 pinned partition optima and 600 minimum vertical splits, 128 exhaustive and 160 seeded exact-line queries with the tree fallback, and 30 complete L basis comparisons against direct chart enumeration. check_cmr.py was run on the real pinned CMR executable, verifying F7 and F7*, 60 recognition comparisons, and 62 exact-line controls. The executable occupies 252040 bytes and the sparse checkout plus build used 2.4 MiB.

CMR positive graphic decisions request the labeled graph using -G and verify its entire cycle kernel over GF(2) in original column order. Loops and parallel elements are restored before comparison. A failing certificate raises an error. Negative graphic decisions use the CMR verdict. Every successful exact-line search is checked in the original coordinates by Gaussian elimination, including the pins-only branch via its original forced span. scalar_relation independently re-sums the returned original indices. paired_space.paired_space implements the pinned 2^r branch and returns an independent basis of actual wedges with two indexed relation masks and a common compatible support. Tests compared 12 W bases and all their returned witness pairs against complete chart enumeration. The real CMR branch also passed 30 complete L comparisons.
