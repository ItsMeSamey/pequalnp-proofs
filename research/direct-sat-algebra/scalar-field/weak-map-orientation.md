# Which way the weak map goes

In the degree-four extension-field projection, let A be the binary complementary quotient and C the GF(16) gate. NO means every A-basis is a C-basis. For full equal ranks this says there is a rank-preserving weak map C→A, and equivalently r_C(S)≥r_A(S) on every labeled subset S. Comparing maximum common basis size tests only existence of a basis passing both. Lucas's connected-image rigidity requires the source of a weak map to be binary, whereas here the binary matroid is the image. See [Oxley and Whittle, On weak maps of ternary matroids, introduction and Proposition 2.1](https://homepages.ecs.vuw.ac.nz/~whittle/pubs/weak_maps_of_ternary_matroids.pdf).

A concrete example within the actual named-plane construction makes this reversal consequential. Let private rank be zero, H=span(e1,e2), A project to bits e1,e2, and C be the two-row GF(16) zero test from four-minor-zero-test.md. Take four physical vectors with low-order-first masks 1,5,6,11. They span the full four-dimensional named space. A's columns have masks 1,1,2,3, so A is connected and has five bases. The C columns have four distinct projective slopes 0,1,9,5 in polynomial basis with modulus 19, giving U(2,4), which is nonbinary and has six bases. There is no violating A-basis, despite strict inequality of the connected labeled matroids. Adding any number of common private coloops embeds the example at arbitrary private rank.

If C has a binary realization, resolution-bridge/binary-weak-map.md supplies an exact containment algorithm: compare the binary A-basis polynomial with the binary common-basis polynomial via shifted principal-minor equality. Its symmetric-versus-arbitrary binary case has an elementary SCC proof. General principal minor equality and rank-one determinant-polynomial identity testing appear in [Chatterjee et al., Characterizing and Testing Principal Minor Equivalence of Matrices](https://arxiv.org/abs/2410.01961). This comparison tests coefficient equality, which becomes support equality here precisely because the common-basis coefficients are binary. In the GF(16) gate they need not equal one. The example above shows restricting to binary-realizable C loses genuine NO instances.
