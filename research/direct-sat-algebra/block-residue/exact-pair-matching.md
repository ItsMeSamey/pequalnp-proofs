# Exact one-round pairing of physical NAND blocks

The optional adapter requires NetworkX 3.7. The existing workspace package is at /workspace/scratch/syn_quotients/tools_lib/networkx. Its sibling networkx-3.7.dist-info/METADATA specifies Python >=3.12 except 3.14.1. No package installation is required in that environment when its parent directory is on the import path. The separate scheduler checker prepends that explicit path and verifies the loaded package location. The production adapter performs the versioned import only when optimization is invoked and requests backend="networkx" to select the pure Python implementation. Dependency or resource exceptions propagate to the caller.

For a seed partition, a node represents one block. Each singleton score in this graph is the original block's 0/1 physical cost. Every admissible union of two seed nodes gets its exact cost from the same original-wire projection, and a positive saving of 1 or 2 becomes the integer edge weight. A matching describes disjoint one-round merges. Its total gain is the sum of the original seed costs minus the resulting partition cost because each group's interface is evaluated against the original gate readers and observations. Zero-gain edges may be omitted. NetworkX max_weight_matching with maxcardinality=False optimizes this sum. Unmatched seed nodes retain their blocks. The adapter recomputes the resulting physical cost and verifies the complete gate cover. With b seed blocks the blossom phase costs O(b³) under the source's arithmetic-operation bound, in addition to the physical pair scoring, seed generation and verification.

exact_pair_partition optimizes a supplied seed or the singleton seed. best_exact_partition compares singleton and optimum fixed-order interval seeds, using the lower cost and preferring the interval seed on ties. Exactness applies separately to the single matching round for each seed. exact_pair_witness derives observations from all exterior clauses, pins and signed equalities, uses the verified partition and delegates solving and original NAND replay to corridor_witness. A partition score is not a SAT verdict. Runtime of the physical solver depends on that score and is additional to preprocessing.
