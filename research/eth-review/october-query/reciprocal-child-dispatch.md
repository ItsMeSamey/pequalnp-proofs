# Root dispatch for the reciprocal source modes

reciprocal_child_machine.py (8b3d5ae1) uses two_sided_cauchy_modes.py for target/column numerators and variable_packet_machine_affine.Description for immutable target/source rows. Its external spec is a supplied legal active D.1 layout with m equal to the number of physical edges, the source's field, and labels indexed by shell, shore and whole old vertex. It checks certain shape and port constraints; it does not certify the source size, full packet construction, all field conditions or an arbitrary purported spec.

At a fixed sample, each nonzero mode (packet,source,target,y0,k) has cost a−i+1+k+2v₂(k!), a row coefficient for each affected actual target site, and integer weights on the original source columns. The enumeration adds indices in nondecreasing order with repetition. Every accepted sparse exponent vector has one generating path because removing its largest index yields its unique predecessor. The total weight stays below the actual birth precision, and the used degree at a packet/target stays within its actual row count. All excluded overweight terms belong to the zero ideal and overcapacity target coefficients vanish. The DFS includes the all-zero tuple, streams children and does not recurse on the number of modes in Python.

The new Description stores the local intact W block, all positive target powers and their row coefficients, and source column weights and their positive exponents. A child word therefore computes the actual reciprocal separated factor at its original birth. Retained old vertices are passed unchanged with their existing edge order. The full-root dispatcher visits every required center and interpolation point at the original guard, sums all child products before interpolation, and calls the existing recovery routine. Default children use direct exact assignment enumeration. Plug-in evaluators must return the full child contraction in the supplied ring; use at further levels requires a separately specified dispatch. The full traversal clock charges each mode setup, tuple, construction of every required group and all child evaluations. With direct children this is not an implementation of the asymptotic reset engine. Finite word formation and each tuple's bookkeeping cost polynomial in the displayed parameters apart from target coefficient word expansion of up to 2^{O(L log s)} and the chosen contraction cost. Root workspaces include interpolation point/value tables and saved jets, all polynomial in the specified finite parameters; children can be streamed.
