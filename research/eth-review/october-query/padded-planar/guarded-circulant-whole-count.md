# Whole count for the aligned guarded circulant

Use the large-v family of guarded-circulant-positive-handoff.md with no unused variables. Let v=2l, n=v+3v/2+1, ν=ceil(log₂ ceil(log₂ n)), R=6ν, and v>4R+2. The filler graph H is the R-th power of a v-cycle. The real graph G on the same vertices is a prism C_l □ K₂ and is a subgraph of H. No alignment of a supplied prism ordering with the cycle ordering is required. Such graphs exist for all sufficiently large even v: order the two copies of each consecutive prism column adjacently on the cycle. All prism edges then have circular distance at most two.

Recognition uses the unordered signed clauses. Reject nonpositive literals, repeated clauses, repeated literals, or clauses of width other than three. The unique maximum-occurrence variable g is the guard (degree vR on this family). Removing it from each guard clause gives H; take its vertex set as the base. Each remaining clause must have exactly two base variables and one private variable. Require distinct base pairs among real clauses, each private variable used exactly once, and verify the full variable list, all degrees, H and G are simple, G⊆H, and the stated parameter equations. Require H to have degree 2R. For distinct i,j link them in a new graph when |N_H[i]∩N_H[j]|=2R, using closed neighborhoods. On a true cycle power these closed neighborhoods are circular intervals of length 2R+1. At cyclic distance d≤v/2 the overlap equals max(0,2R+1−d), since the opposite distance is at least v/2>2R+1. Thus the new graph must be a single spanning cycle. Traverse it and verify from all pairs that H is exactly its R-th power. This last test rejects spurious input graphs.

Here is an explicit polynomial prism check for the large l in this family. Enumerate an ordered adjacent starting pair (a₀,b₀) for a candidate rung and a neighbor a₁ of a₀ different from b₀. Enumerate b₁ adjacent to both a₁ and b₀, distinct from a₀, and require four distinct starting vertices. Given two consecutive candidate rungs, cubicity forces the next top vertex as the unique neighbor of the current top other than its predecessor and its rung mate. The same rule forces the next bottom vertex. Generate l columns, require 2l distinct vertices, and check that the entire actual graph has exactly their rung and cyclic rail edges. On a prism a correct seed occurs in the enumeration and recovers the original rails. All checks are polynomial in the explicit input.

If g=1 the filler clauses are true. For fixed base spins the number of private-bit extensions factors over G edges, with factor w(a,b)=1 for (a,b)=(0,0), and 2 otherwise. This gives the A-child zero-pattern multiplicity h_A(0). A direct constant-state computation uses the verified prism order. For column spin state s=(a,b) put u(s)=w(a,b). Set T_{s,t}=u(s) w(s₁,t₁) w(s₂,t₂) on four states. Then h_A(0)=tr(T^l), by multiplying each rung weight once and each consecutive pair of rail weights once around the cycle. No greedy prefix scores are required to evaluate this expression.

If g=0 every filler edge requires at least one true endpoint. The zero-spin set is an independent set of H. Since G⊆H, all real clauses already have a true endpoint, giving 2^e choices for the private bits, where e=3v/2. To count independent sets of size k≥1, designate one chosen vertex and list the k successive positive gaps clockwise, each at least R+1. There are v choices for the designated vertex and binom(v−Rk−1,k−1) compositions after subtracting the compulsory gaps. Every set is generated k times. Thus the exact whole count is

    tr(T^l) + 2^e [1 + Σ_{k=1}^{floor(v/(R+1))} (v/k) binom(v−Rk−1,k−1)].

The divisions are exact after multiplying by v. The summands count disjoint assignments on the two values of g. All integer computations and output use polynomial bit complexity in the active size; output has at most n+1 bits for the stated family. If a wrapper permits additional declared unused bits, count the verified active core with its stated parameters and multiply by two per unused bit. Charge the resulting binary output length and the cost of handling the declared header. This optional extension is an identity for the count; adding unused bits can change the source dispatcher and its chosen parameters.
