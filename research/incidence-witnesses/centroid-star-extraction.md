# Batched singleton queries through a formula frontier

For a scalar circuit with s binary gates in a projective plane, stop backward traversal from the output whenever a shared internal gate is first encountered. The remaining formula has m≤s internal gates, m+1 leaves and 2m+1 nodes (parallel occurrences count separately). Treat selected lines as queries and points as the data. The symmetric direction is discussed below.

For each distinct stopped gate g, let S_g be its point singleton support, T_g its line singleton support and E_g the incident pairs it accepts whose endpoints are outside both supports. Let t_g=|T_g| and c_g be the number of lines represented in E_g. On a singleton query l, replace a stopped gate's value as follows: use constant one on T_g; otherwise use g(P,0) OR the point variables p with (p,l) in E_g. This is below the original gate for every point set P by monotonicity. It agrees on the tested incidence flags, since a true flag at g is explained by one of its two endpoints or by E_g. Thus the specialized output retains every incident singleton and rejects all disjoint point sets on the original promise.

Use either g(P,0) or one as the default for each stopped gate, minimizing the number of differing queries. Per occurrence the number of updates is at most min(t_g+c_g,N−t_g). A direct line leaf defaults to zero and updates once. Let K be the sum of these counts and let E=Σ_g|E_g| over distinct stopped signals. All corrected gate values across queries can be built with E additional ORs. Evaluate upstream circuits for the data functions g(P,0), and evaluate the frontier formula using the chosen defaults; this costs at most s gates altogether. Indeed the frontier internal gates are unshared and cannot belong to a stopped gate's upstream cone. Every formula node now has a baseline value, possibly depending on point inputs.

## Ancestor paths in two context lookups

Each formula edge from a child to a parent supplies a unary function, using the sibling's baseline in the original AND or OR. Every monotone unary context with point-dependent coefficients is represented by the pair (a,b) of its values at zero and one. Applying it to t costs ≤2 gates as a OR (b AND t). Appending an elementary edge context costs ≤2 gates, by applying its one gate to each endpoint. Prepending an elementary context of the form t OR w changes (a,b) to (a OR (b AND w), b), and prepending t AND w changes it to (a, a OR (b AND w)). These also cost ≤2.

Recursively remove a centroid from each component of the undirected formula tree. At each centroid compute every upward path context to it from a descendant in that component and from it to an ancestor in the component. Extend one edge at a time. Incomparable vertices require no table entry. Each component edge costs at most two gates at this level. The centroid halves component size, so at most floor(log₂(2m+1)) levels have components with any edges, each with ≤2m edges. The total preprocessing cost is bounded by 4m floor(log₂(2m+1)). For a query from descendant x to ancestor y, the first centroid separating the endpoints (or equal to an endpoint) lies on their unique path. Its two table entries evaluate the requested path context using ≤4 gates, including paths with an empty half.

For a line query touching k≥1 formula leaves, take the union of their paths to the root. Compress all unary chains. This leaves k updated leaves, at most k−1 genuine branch vertices and at most one additional unary root, hence at most 2k−1 compressed edges. Transfer each changed value along its chain by a context query, stopping at the immediate child of the upper branch, since that branch uses two changed child values. Apply the original gate at each such branch. For a unary root include its edge in the path query and no separate gate is needed. The specialization therefore uses ≤9k additional gates. An untouched query uses the default output. All preprocessing gates can be shared among all outputs.

## Bound and scope

The resulting multioutput circuit has at most s+4m floor(log₂(2m+1))+9K+E gates. The simultaneous sparse-query cut lower bound gives Nq as a lower bound on this quantity. Its hypotheses are positive incident singletons and rejections on disjoint payload sets of size at most q; this can be checked in lean/Research/SparseQueryCut.lean, theorem simultaneous. Constants may be propagated out of nonconstant outputs or treated as baseline input wires with singleton supports empty or universal. On the original sparse-line promise, singleton line queries are valid on every set of points. Exchanging the sides gives singleton point queries tested on line sets through size q, which still suffice for that theorem. Under a smaller bilateral promise allowing q−1 per side, use only q selected neighbors as the positive set in per_query with r=q−1, retaining the original full star for the qualifying slots and the disjoint negatives. UniqueStarCost then gives N(q−1).

In particular, if all stopped gates depend only on points, E=0 and K≤m+1, independently of their support sizes. The same conclusion applies if their positive-flag fingerprints are explained entirely by point singletons (no accepted line singleton and no exceptional flag). Then Nq≤[10+4 floor(log₂(2s+1))]s+9. For q=401, a putative s≤646424 has floor(log₂(2s+1))≤20 and the right side is at most 90s+9, strictly below Nq. Thus such a circuit cannot exist. More generally, essentially pure signals with E=0 but varying supports on both shores are controlled by their minority support sizes across the chosen set of queries. The inequality does not bound that cost on every unrestricted circuit.
