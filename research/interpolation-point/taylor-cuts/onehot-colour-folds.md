# Source-checked one-hot graph reductions

The input parser recognizes disjoint three-variable XOR rows and binary exclusions with signed event literals. The complete internal triangle of exclusions fixes the sign of each local event. After undoing these signs, the XOR right side must be odd. Each nonempty pair of vertex triples must be joined by exactly three binary exclusions, bijectively matching their events, without any additional clauses. Tautologies, exact repeats and unused bits are harmless. Propagating event names through the matchings tests for ordinary globally synchronized graph colours. This is recognition of a displayed presentation; it does not reconstruct arbitrary hidden XOR bases or search for a core amongst extra guards.

For unsynchronized edge matchings, first remove vertices of current degree at most two until no such vertex remains. Each assigned neighbor forbids only one local colour, and therefore every colouring of the remaining graph extends. This argument does not depend on a cycle's label permutation. If the remaining graph synchronizes, solve it and restore the peeled vertices in reverse using the original edge matchings. Otherwise report UNKNOWN. In particular every path of internal degree-two vertices and every standalone twisted cycle can be peeled.

For an ordinary synchronized core use the following decision reductions:

* A bipartite component admits a two-colouring. Repeatedly peel vertices of degree at most two and restore any locally available colour in reverse.
* If N(u) is contained in N(v) for distinct u,v, remove u and later assign it the colour of v. The vertices are nonadjacent. This preserves existence, and can change model counts.
* Two distinct common neighbors of adjacent vertices must use the same third colour. Identify this pair, taking the union of their neighborhoods, and copy the merged colour back. An adjacency between the identified pair is a contradiction. More generally a vertex whose neighborhood is nonbipartite cannot belong to any properly three-coloured graph.
* For a subcubic core, search for a vertex v with nonadjacent neighbors a,b and connected G−{a,b}. Assign a,b the same colour. Order the others by reversed BFS from v in the connected remainder; each vertex except v has an uncoloured parent, and v sees a repeated neighbour colour at the last step. Greedy extension therefore succeeds. Only use this rule when the explicit conditions hold.
* Find a clique separator of size zero to three. Recurse on each component of its complement together with the separator. A negative child certifies UNSAT; positive children with a common cut can permute their three colour names to agree because colours on the cut are distinct. All positive children give a full witness. An inconclusive child permits UNKNOWN if no contradiction was found. Without a recognized rule report UNKNOWN. A supplied subproblem-count cap can also produce UNKNOWN.

The public solve function returns status, original assignment or None, and rule metrics. It checks every returned bit assignment against all source clauses and parity rows, with unused coordinates set to zero. These are decision reductions. With a capped number of recursive subproblems, all reductions and witness lifts require polynomial work per subproblem; no inference that a stalled instance is unsatisfiable is made.

A protected checker used randomly permuted variables and signs and compared against independent ternary search on every labelled graph through five vertices (1,100 graphs including the empty graph) and 300 random eight-vertex graphs. It exercised both domination and forced-equality contractions. A Petersen graph is nonbipartite with no degree-two vertex, twin or diamond, and is solved by the subcubic order. Two Petersen graphs glued along an edge exercise clique gluing and recolouring. The odd wheel gives UNSAT by neighborhood obstruction, while the Clebsch graph stalls. The checker also covers a genuinely nonsynchronized matching five-cycle, a missing detection promise and a zero subproblem budget.
