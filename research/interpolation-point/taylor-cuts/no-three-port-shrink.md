# Hard cubic OR/COPY graphs having no proper three-port region

Start with a connected NP-hard class of exact 3-CNF with distinct variable triples and no repeated variable in a clause. Linear 3-SAT suffices (https://arxiv.org/abs/0708.2336). Components can be linked transparently by bridge clauses with one fresh variable and one chosen endpoint from each adjacent component. For bounded initial occurrences if desired, first split occurrences into distinct variable clones, enforce each original variable's equality by a binary implication cycle, and pad each binary clause with a fresh forced-false variable from a fixed punctured minimally unsatisfiable linear 3-CNF. Its existence is established in the cited work; all its scopes are distinct. The new original and link triples are distinct, and its maximum degree is constant.

Replace each variable by four clones and each original clause by the 64 clauses on all choices of one clone per literal, preserving signs. Equal clones lift any original model. Conversely any choice of one clone per original variable projects any lifted model to an original model. Expand each cloned variable into an arbitrary trivalent tree of COPY gates with one leaf wire per occurrence. This cubic Boolean tensor network is satisfiability- and count-fiber-preserving for every fixed assignment to the cloned variables. The clone expansion itself preserves satisfiability, without asserting equal counts.

After removing any three cloned variables or fewer, any nontrivial partition of the remaining variables crosses at least four distinct remaining clause scopes. Some original block contains both sides, because each original variable has a surviving clone and the original incidence graph is connected. If a surviving clone part within that block is split, each pair in the other two parts yields a crossing triple and there are at least four such pairs. If no part splits, all remaining triples in the mixed block cross. This argument concerns incidence wires between trivalent Boolean factors, before any atom-level matching replacement.

A cut of at most three wires splits at most three COPY trees. All unsplit trees must be on the same side by the preceding paragraph. On the other shore let q be the number of clauses and s the number of split trees. Each split costs at least one internal COPY edge. If q≥2 and s≤2 then at least s+q(3−s)>3 total wires cross. If s=3 then no external wire may cross, so every opposite clause must use precisely the three split variable clones. There is at most one such scope. Thus q≤1. A shore meeting at most one clause and containing no entire variable trees induces a forest, because any one clause touches three distinct variable trees. A nonempty induced forest on v vertices in a cubic graph has edge boundary at least v+2. Hence the shore is a singleton, independently of the COPY layouts.

The giant complementary shore exists but testing whether it has any feasible boundary is NP-hard on this construction: removing a clause allows a projection avoiding the particular deleted clone triple; removing one COPY node allows a projection avoiding its entire cloned variable. Other selected variables and clauses remain intact, so either kind of residual model projects to an original satisfying assignment. The converse extends from a model of the complete formula. Consequently a supplied algorithm that computes every large three-port table in polynomial time would also decide this NP-hard family. Recognizing and reversing the twin construction or globally changing the representation remains possible.

For a constructive comparison, any already nonnegative matching block with at most three external ports has at most eight support patterns. Determine these by forced-vertex matching and replace by a fixed finite support representative of at most c vertices. On a family supplying, at every stage, disjoint blocks of size ≥2c covering ≥αN vertices and computable in polynomial time, N_next≤(1−α/2)N, hence O(log N) stages at fixed α. The promise is a real requirement. Computation of arbitrary signed or exact-weight block tables does not follow from these support tests. The cubic hard sources above have zero coverage for native proper regions in all layouts.
