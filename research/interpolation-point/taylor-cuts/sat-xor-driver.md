# Staged exact SAT+XOR driver

Call solve_sat_xor(n, clauses, xor_rows, stages=..., budgets=...). Clauses use signed one-based integer literals; XOR rows use little-endian integer variable masks and binary integer right-hand sides. Each result includes status, an original-variable SAT witness or None, input metrics and an ordered stage log. Original unsimplified clauses and original XOR rows are replayed before accepting a SAT result.

The default order is ANF consequences, signed resource-clique certificate, inferred long choice covers with parity SCC peeling, binary closure-interaction cover, native-polarity Horn with exceptions, signed Horn semilattice compilation, a balanced semantic tree over clause violation cells, and exhaustive search on a Gaussian parameterization. The ANF stage replays selected clause sources and forwards verified affine equations. The resource stage replays its certificate. Choice recognition can decline an input or stall inconclusively. The closure_cover stage checks normalized width at most two and otherwise skips. It solves eligible instances exactly by pinning a minimum vertex cover of the generator interaction graph and reports the cover and XOR ranks when available. Its default worker deadline is 0.5 seconds. The Horn stage skips if its effective-rank seed bound exceeds 50,000; the semilattice stage skips after exceeding support 1,024. The tree minimizes the exact count of violated clauses and reports interface and leaf statistics. The fallback traverses a Gray-code ordering of the free linear-system coordinates. It reports the exact visitation count through 64 bits and reports the bit length and a power-of-two flag for larger counts. Stage skips, crashes, poor witness validation and timeouts do not produce UNSAT. A logged definitive UNSAT from an exact backend is trusted; the driver does not produce one universal proof format for all backends.

Budgets specify per-worker elapsed seconds. The optional stages default to 0.5 seconds each; brute has no default deadline. Supplying a zero budget skips a stage; passing an explicit stage sequence runs only that sequence. To bound all workers, budget every enabled stage including brute. When none returns a decision, the driver reports UNKNOWN. Each backend runs in an isolated Linux fork child; its startup, computation and result serialization share a monotonic deadline. On timeout the parent kills and reaps the child. The worker exports through an anonymous temporary file. Metadata, including derived rows, is capped at 8 MiB. The complete result has a cap of max(8 MiB, 2·ceil(n/8)+4096 bytes) to accommodate an original n-bit witness; oversized exports become errors. Storage and decoding for a legitimately large witness therefore depend on the input dimension. The timeouts are worker deadlines. Parent-side input preparation, bounded result decoding, process reaping and original witness replay add wall time beyond those deadlines. Timing and which optional stage finishes can vary with system load. With uncapped brute and ordinary system resources the driver is a complete deterministic decision procedure; its exponential worst case remains.
