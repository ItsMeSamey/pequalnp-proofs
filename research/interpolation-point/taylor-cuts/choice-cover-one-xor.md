# Disjoint signed choice covers with one parity equation

The supplied cover clauses have pairwise disjoint variable sets. A signed cover literal is an event. On each group require binary clauses forbidding every pair of its events, so exactly one event is true. Other clauses are pairwise conflicts between events in different groups. Validate that each connected component of the cross-conflict graph contains every cross-group pair of its own vertices. It may contain several events from the same group, with no edge between them in that cross graph. Variables outside the groups can occur in the XOR or be unused. Tautological or otherwise unsupported extra clauses are outside the parser's contract. A designated empty cover is unsatisfiable.

Give each cross-conflict component a resource, including isolated events. View each event as a labelled edge from its group to its resource. Satisfying cover choices are exactly matchings saturating all real groups. Parallel options with the same two endpoints can carry different parity weights and must be kept. Allow more resources than groups by adding sufficient dummy rows adjacent to all resources with zero weight. Any real saturating matching extends to a perfect matching, and every padded perfect matching restricts to one. This proof is for decision and witnesses; multiplicity from dummy permutations is immaterial here.

Toggle the parity target for negative XOR literals, cancel duplicate underlying variables modulo two, and translate signed event variables relative to the all-events-false baseline. Each event then has weight one precisely when its underlying variable has odd XOR multiplicity. A surviving XOR variable outside every group can supply either residual parity freely. Obtain a deterministic baseline matching by augmenting paths. If unavailable return UNSAT, and if its parity fits (or a free bit can fix it) decode it.

For opposite parity with no free bit, direct each option of row u to the current owner v of that option's resource. Give the arc weight equal to the option's weight XOR the current weight at u. Any simple directed cycle replaces its rows' current options by the cycle options, permuting their resources and changing parity by the cycle weight. Self-loops permit switching between parallel options. Conversely every second perfect matching induces a permutation of the baseline rows, with the selected option attached to each arc. Its cycles include length one even when only the selected parallel edge differs. The sum of their weights is the total parity difference. Thus an opposite matching exists exactly when the residual contains an odd directed cycle.

For each root u search the parity double cover for a path from (u,0) to (u,1). From its odd closed projection, a repeated internal vertex splits off a closed segment; keep the segment if odd and otherwise remove it. This strictly shortens the odd walk until a simple odd cycle remains. Decode the flipped matching, set the free parity variable if applicable, then evaluate the original signed clauses and XOR on the returned word. With R resources and E padded options the searches and matching take O(R(E+R)) work and polynomial storage, in addition to checking the explicit group/conflict promise and reducing closed walks. A straightforward segment-shrinking implementation can use O(R²) time on the one walk; each doubled-state BFS path has length less than 2R. All parts are deterministic.

The standalone implementation and finite checker are choice_cover_one_xor.py and choice_cover_one_xor_check.py. Exhaustive four-variable sign/resource/parity cases and small random cases gave 8,792 brute-force matches, of which 2,901 were UNSAT. Additional fixtures distinguish missing matchings, unattainable parity, and a parity-changing parallel switch. The result addresses one XOR; cycle alternatives need not combine independently under multiple XORs.
The single-XOR step applies deterministic bipartite correct-parity matching. See [El Maalouly et al., ISAAC 2023](https://drops.dagstuhl.de/storage/00lipics/lipics-vol283-isaac2023/LIPIcs.ISAAC.2023.28/LIPIcs.ISAAC.2023.28.pdf). Short cover clauses require supplied cover indices; the recognizer can infer longer covers when every remaining clause is binary.
