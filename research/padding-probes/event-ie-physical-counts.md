# Counting original physical words with Gaussian inclusion-exclusion

event_ie_solver.solve has the same physical inputs, signed pins, codebooks and raw/macro backend choices as event_gaussian_solver.solve. Its omission_cap and branch_cap each permit None or a nonnegative integer. The separately frozen Stage 4 branching backend requires a nonnegative integer exception_cap (default zero); None is outside its API contract. Its early pin-conflict branch currently bypasses the generic exception_cap validation, and the source freeze is preserved.

For complete results, counts[0] and counts[1] count distinct canonical physical byte words producing those outputs, with branches satisfying all supplied pins. UNKNOWN returns no counts. Each positive count must have a reconstructed word with that output. The wrapper validates the source checksum given by counting all distinct listed alias IDs after consistent pins. Each free ID contributes a binary choice. The canonical spellings distinguish the two values at each occurrence, so their assignments are bijective with the resulting physical words. Contradictory pins give zero words.

**Why counting event records counts words.** A physical word uniquely fixes the codec and every occurrence bit. Starting at the true initial control and bottom stack, that byte word uniquely determines the real machine's entire control and stack trajectory. On a valid raw event-record assignment, the before/after registers must follow that trajectory by induction. A push saves the old top, and each pop's restore constraint refers to precisely that push; both values are fixed. Each synthetic no-op has the prescribed selector and unchanged state. On a macro assignment, the fixed prefix determines every initial symbol, and each whole-spelling record has its deterministic entry, exit, physical bit and spelling. A returned symbol on a marker pop comes either from the fixed prefix or the unique matching marker push. In both builders domains are sets of distinct records and the final output is determined by the actual terminal control. Conversely the real trajectory supplies all required records for each legal word. The forward construction's overapproximation affects refusal and table sizes but adds no freedom to a globally consistent assignment. A codebook gives distinct binary words to distinct records of each event, with unary domain constraints excluding unused representations; therefore an original satisfying record assignment has exactly one global Boolean encoding.

The generic backend counts the solutions of the global hull equations while excluding each omitted local tuple. Inclusion-exclusion runs over subsets of excluded tuples and counts each Gaussian subproblem exactly (zero or a power of two). Conditional counts recover an assignment for each positive output. The omission budget limits eligible descriptions and the branch budget counts subset evaluations including recovery. Neither budget covers actual codebook construction, physical preprocessing, Gaussian elimination cost per term, arbitrary-precision count arithmetic, or original-byte reconstruction and replay. Complete physical counts must sum to 2 raised to the number of free IDs. This is an additional consistency check; the bijection above proves each individual count.
