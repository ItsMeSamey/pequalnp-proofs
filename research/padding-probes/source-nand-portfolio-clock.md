# NAND portfolio cost and scope

Both entry points accept sparse signed clauses of width at most three and sparse source pins. The pure compiler produces an ordinary NAND circuit. The mixed compiler keeps clauses of width one and two as exterior tests and represents each selected signed pair by a shared OR wire. It greedily chooses a most frequent pair among uncovered ternaries. Its counted pair visits are three times the sum of remaining ternaries over the passes. Computing the frequencies, breaking ties, scanning uncovered rows and creating compact wire names all take polynomial time in the input length, including binary variable labels.

For either compiler, the interval optimizer sees every wire observed by an exterior test. It finds the minimum number b of non-bijunctive blocks among admissible contiguous partitions of this particular gate order. In the mixed compiler singleton blocks give b at most the number of selected pairs, since singleton negations are bijunctive. If W includes all gates, active inputs and exterior occurrences, partition construction costs O(g³ poly(W)) for g gates. Enumerating the binary sides of b exceptional blocks and solving their remaining binary predicates costs O(2^b poly(W)). The returned input is replayed on the gates and original signed rows. Every SAT result includes canonical physical bytes from a further fully pinned source replay. Representation costs depend on used or pinned names and their bit lengths, including the time to emit the bytes.

Both launchers are NAND-first. They also compute the fallback covering-code search tree ceiling before dispatch, including greedy small block construction. The reported comparison is between branch counts. It does not establish an ordering of elapsed times. A competitive NAND route can run before a polynomial Horn or affine shortcut. The mixed successor tries the mixed candidate first when enabled, and skips pure compilation on success. Disabling it calls the pure launcher directly. If the certified branch count exceeds the cover ceiling or the user's NAND cap, the candidate is skipped; the pure launcher delegates to the chart/physical/cover portfolio. A cover node cap concerns only that search. Capped routes can return UNKNOWN; they do not imply UNSAT.

With the default finite set of stages and uncapped complete cover, each of the at most two dispatched NAND searches consumes at most the computed cover ceiling times a polynomial in the original input length. The other terms are the previous portfolio clock and polynomial preprocessing, witness checks and output. Thus including the new routes preserves the prior worst-case exponent. This bound gives no instance-wise minimum against a shortcut that the NAND-first policy reaches later. See source-cover-portfolio-clock.md for the cover construction and earlier stages.
