# Exact marker-block domains for a visible stack schedule

Take the actual fixed prefix and the two complete, distinct, canonical byte spellings at each marker. A marker chooses one spelling. At its first byte each stack has a supplied operation type, fixed across choices and all reachable configurations at that position. An operation is stay, push one symbol above the old top, or pop one nonbottom symbol. All subsequent bytes in that spelling must stay on every stack. Stay preserves its top. Control and the first pushed symbol may depend on the actual byte and full tuple of current tops. A finite acceptance mask or enable test remains part of the original machine. The fixed prefix can be executed byte by byte from the known initial configuration; carry its exact resulting stack as initial cells for matching subsequent pops. An easier implementation retains prefix events on the original axis.

For a spelling w, entry control p and entry top tuple a, execute the first physical byte using the actual table. Record its next control p' and the actual operation and pushed symbol of each stack. On a stay use a_i as post-event top. On a push save a_i and use the actual new symbol. On a pop inspect a_i, prohibit bottom, and enumerate a candidate restored top h_i. The paired push record must later verify its saved value equals h_i, or a known initial cell must verify it for a prefix-origin return. This enumeration is essential: two stacks with the same pre-pop top can produce different terminal predictions after the same second byte by exposing different underlying symbols.

Let t be the resulting joint top tuple. For each tail byte c in w[1:], run the exact table at the current control and t. Require stay on all stacks and record the resulting control. The full sequence of pre-byte tops is therefore a for the first byte and t for every tail byte. For each candidate emit a macro record containing spelling choice, entry and exit control/top tuples, and old/restored tops. Restrictions on the values inspected within the tail must be evaluated while simulating it; comparing only boundary states or net height would lose them. A path push followed by pop in the tail has net height zero yet fails this verifier. No synthetic byte is required even if the two spelling lengths differ.

Use the path of marker boundaries, signed alias links between marker choice records, and saved/restored-top links for the fixed visible schedule. Check initial and terminal registers. The original byte run restricts to these records. Conversely, take any satisfying macro records. Induct over blocks, maintaining the full real stack below each recorded top. For a matching return, LIFO and its saved-top constraint identify the true restored symbol. Running the tail on that symbol gives exactly the recorded exit registers, and the next block starts on the same registers. Concatenating the selected original spellings yields the physical formula. Re-encode its key, reparse signed aliases, and replay the raw predictor before declaring an attained outcome.

Schedule verification must rule out off-schedule transitions on every relevant path; erasing nonconforming records alone would change the fiber. A sufficient verifier checks all candidate boundary states/tops consistent with the known stack heights and all legal restored-top guesses. A proved overapproximation by position of reachable controls/tops can remove impossible rows: initialize exactly, propagate both spellings, and propagate every possible restoration on pops (using the known height to restrict bottom). If any propagated run violates the schedule, conservatively abstain. This can reject schedules which only fail for spurious restoration guesses. Do not claim exact semantic recognition on this basis. A common matched-push/return graph likewise cannot be used when alternative spellings imply different push/pop pairings without a further proof.

Let Q be the number of controls, T the product of top alphabet sizes including bottoms, c the number of spellings per block, and R the product of top-alphabet sizes of stacks popped on its first byte. There are at most c Q T R domain records at this block, often fewer. Explicit raw-table validation costs at least its input size (for dense tables on a byte alphabet, O(256 Q T) row inspections times action size). For each spelling and each possible fixed t, compute the tail transformer control-to-control-or-failure by right-to-left composition. This costs O(|w| Q T) table inspections and O(Q T) rolling entries; on a failed transition store the first violating physical offset if required. Then instantiate first-byte records in O(c Q T R) further lookups per block, times record, stack-count and indexing costs. Whole-spelling processing remains charged even when all rows compress to a single relation. An on-demand forward verifier costs O(|w|) per explored record instead. For a prefix already executed from the exact initial state, charge all bytes and the actual resulting stack.

For a supplied checked width-W decomposition on B marker blocks and their links, the remaining Boolean two-outcome search costs O((B+decomposition size) poly(W,record size) D^(W+1)), where D is the maximum actual domain size. Charge O(B D²) if pair relations are fully materialized, with the actual number of links in place of B when needed. Relative to the byte-event scheme this removes internal path vertices and their per-bag dynamic programming work. It neither removes physical input and raw-table verification nor guarantees a smaller D; pop records still carry the restored top tuple. Severe control-domain costs may dominate. Boundary-domain elimination must retain a lift per surviving row. Resource exhaustion cannot certify the missing output.
