# Checked stack synchronization for signed physical aliases

On the canonical DIMACS fiber, mark one actual branching byte per whole marker line. A chart supplies each marker's signed underlying ID. Require each repeated ID to appear exactly twice and its intervals to be properly nested, certified by a linear scan with a stack. Singletons are unrestrained. Store the normalized bit (physical sign XOR offset). This retains both correlated sign positions within one marker spelling. Do not expand all 2^b assignments to the live IDs.

At an annotated open the predictor must itself push a symbol; mark that frame with ID and normalized bit. At a close require the matching marked frame, prune unequal bits, and require a predictor pop when bits match. Other pushes create neutral frames; a neutral-byte pop may remove only a neutral frame. Removing alias marks from a reachable stack recovers the predictor's original stack. Reading its marked frames bottom-to-top recovers the currently unmatched IDs and normalized bits. These two inductive invariants show every fully simulated word respects the signed equalities and every legal word with synchronized operations is preserved. If a reachable potentially relevant transition has the wrong discipline, abstain rather than silently deleting it. This first-prefix check can conservatively decline even on an inconsistent suffix. Thus an exhausted successful run recognizes a sufficient class; it need not detect every machine semantically synchronized on just its completing legal paths. Original witnesses must reparse from bytes and validate all repeated IDs. A disagreement certifies an error somewhere among the equivalent pair; common truth is known to be UNSAT here, so a positive prediction individually identifies an error. Constancy is not correctness.

The independent-marker graph still has O(L) byte edges. The original stack alphabet Γ grows to at most (1+2p)|Γ| for p repeated names; no 2^b frontier factor is paid, even for unbounded nested depth b. Including graph/table reading and output replay, recognition and exact evaluation cost polynomial time and space in the explicit input. For V vertices, E edges, Q controls and C reachable augmented entries (≤VQ(1+2p)|Γ|), sparse saturation has O(CVQ+C²) facts/waiters and O(CQE+C²VQ) possible arc scans/return joins, each involving polynomial bit work. Include all unsuccessful/capped work. Additional predicates or an oracle that checks arbitrary code implements the specified table are not part of this clock.

The VPA product over a common visible alphabet partition is classical [Alur and Madhusudan, §2.2](https://www.cis.upenn.edu/~alur/Stoc04.pdf). The native construction allows annotation by physical edge and checks predictor operations in actual reachable states, so it need not be literally visible over the 256 raw bytes. Exact language lower bounds for misaligned independent stacks are not decision lower bounds. A stronger finite reduction is in crossing-alias-hardness.md: general signed alias charts let a fixed byte DFA express SAT by streaming clauses and using aliases for repeated variable occurrences. Unrestricted disagreement is NP-complete on that succinct representation; explicit byte enumeration can be exponentially larger. Even without repeated keys, an arbitrary polynomial executable reading an immutable challenge can realize the independent hard-fiber construction in padding-disagreement.md. Neither result entails uniform SAT separation or equivalence from sampled executions.

The finite obstruction strengthens to at most TWO occurrences per alias even when the target is a fixed DFA. In the construction in paired-crossing-hardness.md, chain ternary equality constraints through each variable's literal occurrences; use each occurrence copy once in its equality row and once in the source clause. Each link belongs to two adjacent rows. Alternate equality and OR row groups with private satisfiable ORs for padding. Thus fixed-state checking recovers all of SAT without unbounded alias frequency. The additional structure enabling the positive procedure is checked synchronization and proper nesting, not the number of copies alone.
