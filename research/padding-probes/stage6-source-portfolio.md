# Source 3-CNF through the paired physical event portfolio

stage6_source_solver.compile_source(n, clauses, exact_twice=False) builds the paired reduction specified in paired-crossing-hardness.md. Its optional cyclic mode is the construction in paired-orbit-optional-exactly-twice.md. Neither original reduction note provided an executable compiler. For each strict input triple the ordered literal occurrences, equality checks, OR checks and dummy rules are unchanged. Each variable's equality checks are consecutive in first-occurrence variable order, and the pairs always print equality before OR. Width-one/two clauses can additionally be represented by repeating the last literal; an empty clause is represented by opposite triples on one fresh internal variable. The original clauses remain available for independent validation. An empty conjunction has a single physical enable marker and no equality/OR blocks.

For m prepared triples the physical challenge is empty, its codec dimension is 18m, and its header states 72m+6 variables and 18m+9 clauses. The predictor is a single fixed complete byte table: skip the header and eight carrier clauses, consume the minus sign at the first byte of each marker, check equality then OR on the sextuple, and require the trailing enable and a complete line. Every physical DIMACS carrier is unsatisfiable. The proposition being decided is existence of a positive prediction, which is equivalent to satisfiability of the original pinned source. The deliberately different predictor in padding_cnf.predict must not be substituted.

The compiler exposes slots_n, signed aliases, occurrence IDs, anchors, word(mask) and lift(raw). word requires a satisfying original assignment and returns an enabled physical witness. lift validates the canonical challenge, signs, all alias repetitions, equality/OR tests and enable; inactive original variables default to zero. The public solver also replays the fixed table and restores any requested values for inactive variables before checking every original clause and pin. A consistent active source pin is imposed on one of its occurrence IDs, since on positive words the variable's equality chain propagates it to all occurrences. Negative words remain possible by choosing enable zero.

Use stage6_source_solver.solve(n, clauses, exact_twice=False, source_pins=(), stages=None, fallback_limit=0), with the optional arguments passed by keyword. The result has status SAT, UNSAT or UNKNOWN, a packed source witness and physical bytes on SAT, and an attempts list. Source pins may be a mapping or a list of (one-based variable, zero-or-one bit) pairs. The default sequence uses gaussian, compressed, flat, rank2 and block. Explicit names additionally include ie and period. Each stage can be a string or a pair (name, options); options override its finite default budgets in _DEFAULTS. Physical stage selections cannot insert their own occurrence/ID pins, schedule, or target, which would change the source decision. Use backend raw or macro and an optional record codebook where supported.

A replayable positive sample decides SAT, even if that individual stage exhausted a later search budget. Only a completed constant-zero physical result certifies UNSAT. An unrecognized chart, projection or budget miss allows the next stage to run. The source fallback enumerates only unfixed occurring original variables. Its assignment budget is zero by default; None is explicitly exhaustive. If the bounded stages and fallback do not decide, return UNKNOWN. The pipeline is exponential in the worst case; no general speedup is established.

Charge the source occurrence and physical description sizes, the fixed finite table, each executed stage's preprocessing/eligibility checks, and its own codebook, relation, Gaussian, decomposition, counting, witness and physical-replay costs. A cap on the search phase does not cap all preprocessing. A physical witness has O((m+1) log(m+2)) bytes; packed source masks also charge their actual bit length, including high-index inactive pins. Fallback examines at most the smaller of the specified assignment budget and 2^u assignments for u unfixed occurring source variables. The arithmetic reconstruction and original clause/pin checks are additional per assignment. Source-level counting is intentionally not reported: physical counts have dummy multiplicities and omit unconstrained inactive source variables. The default open-chain multiplicity per satisfying assignment on occurring variables is 7^(2m); cyclic mode gives 2^(3m).

Run with both the physical-bdd-union and sibling compression directories on the Python module search path; projected backends use the shared affine-cover modules there. The implementation was produced source-only. Independent exercise of the actual compiler, finite table and original portfolio belongs to the separately authorized verification lane.
