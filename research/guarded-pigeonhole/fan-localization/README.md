# Localization of a split apex in a binary two-sum tree

In a fundamental bipartite chart, cycle coordinates on nonbasis elements and cocycle coordinates on basis elements together give the selected vertices. Disjointness means every selected vertex has even selected degree. Splitting an apex yields a private path l–a–b–r with l,b on the basis shore. Impose d_l=c_r. In addition there are three arbitrary ordinary linear scores. Use an oracle for arbitrary bipartite three-score instances. All claims concern decision with a fixed requested score z.

## Finding the host

The triangle {l,a,b} and triad {a,b,r} project on a three-connected torso either to zero or to words of length three. Indeed a triangle crossing a limb contributes the virtual coordinate for an odd boundary mode and uses at least one real element there. A zero projection places the whole circuit inside one limb by minimality. The overlapping middle elements force the projections to be simultaneously nonzero or simultaneously zero: if all of the triangle is in one limb, the triad meets at most two torso slots. For nonzero projections the middle slots are distinct and the outer slots are distinct by binary orthogonality. A middle element displaced into a limb would form both a parallel and a series pair with the virtual element, an isolated two-element component, impossible in a proper connected limb. Thus both middle elements are real. If l is displaced into a limb its two-element cycle with the virtual port p implies d_l=d_p. The dual argument transfers c_r to the virtual port on its limb.

Consequently at most one three-connected torso sees the tie. If the middle elements have one owner, the projected triangle and triad occupy four slots there and exclude a series or parallel owner. If the middle vertices have different owners, the intervening proper two-separation makes ab a bridge in the original chart, as detailed in ../mixed/fan2/README.md. In the tied-on mode the private vertices have equal bits and cannot both be selected across a bridge (sum selected degree parities on one side). With unweighted private bits the tied-off mode permits deleting both. The resulting components containing l and r each carry a nonzero tie coefficient; the disconnected four-score reduction applies. Start from the canonical private bits, whose ordinary weights are zero. Weighted bits arise later at the host.

## Three-score limb tables

Cut away one entire limb of the common host and restore the virtual point q on both sides. Its port mode (c_q,d_q) has three possible values 00,10,01. Transfer the tie using the proxy identities above. In the exterior choose a tied feasible model for each port mode. Mode 00 uses zero. For 10 seek a pure cycle with c_q=1,c_r=0 by elimination (using the current proxy for r). If none exists, noncoloop q implies c_q=c_r throughout the cycle space. The global original canonical support {l,r} has tie value one, and its restricted exterior witness then has mode 10 by disjointness. For 01 apply the dual argument. This construction uses the real exterior, before replacing other limbs.

Write e_m for the three-bit exterior score. Any prescribed offsets on the three modes are a constant plus a linear function of the two port coordinates. Ask the limb oracle for z with offsets e_m. A positive answer glues to the matching exterior witness. Otherwise z+e_m is missing from the limb score set S_m for each m. For fixed m replace its offset by z+k and keep the other two offsets fixed. The oracle then tests exactly k in S_m. There are at most 21 extra queries. This works even when every limb would ordinarily require a fourth marker for a pinned-mode query.

For each limb choose one attainable baseline score per mode. A successful model uses some deviations from the baseline. Preserve an independent subcollection summing to the same three-bit total, discarding dependent subcollections of sum zero. Thus at most three limbs need exceptional entries. Enumerate the exceptional limbs, modes and attainable entries; leave other mode entries at baseline. Every table still consists entirely of attainable entries, so every returned witness glues without extra pins. For each choice all tables are affine offsets and give a weighted three-score instance on the host, with the special tie retained.

## Removing private weights

Choose a basis containing l,b and excluding a,r (the pair l,b is independent and deletion of a,r preserves rank by cosimplicity). The triangle and triad give the private path. If the lr entry exists pivot on ab, toggling lr, and interchange the private names in the new chart. Linear scores transform linearly. In the resulting chart write L for ordinary core score, t_l,t_r for terminal weights and u,v for private weights at a,b. Off permits bare targets z,z+u,z+v. If all fail, merge the apex, give it weight u+t_l+t_r, and add (u+v)F to the bare score L, where F is the neighbor parity on the l side. Query z+u. On active assignments the two neighbor parities agree and give both private bits; this query is precisely the original active condition. An inactive false positive would hit one of z+u,z+v in the bare graph. Thus each host call is an ordinary one-apex three-marker call whose canonical split has this host as its entire three-connected matroid.

Together these give a polynomial Turing reduction to the three-connected canonical split case, given a proper decomposition and the established bipartite three-marker oracle. One can find a proper split deterministically by minimizing the submodular matroid connectivity function with two fixed distinct elements on each side, enumerating the four fixed elements. A rank-one common subspace supplies the virtual column. Recursing yields linearly many bags since the sum over bags of size minus two is invariant.

## Rank-two boundary around the fan

With both attachment shores nonempty, the core/fan common subspace has basis e_l,w where v_l=e_l, v_b=e_b, v_a=e_l+e_b, v_r=e_b+w. The external columns span w and e_l (cancel remaining entries of a column incident to l with external basis columns). Boundary flux P and trace delta satisfy P_w=c_r and delta_l=d_l. The tie is exactly P_w=delta_l. For tied-off, P_l and delta_w are independently free. For tied-on they are equal, with both choices attainable. These six states describe the fan, without assumptions on the actual core's feasible states. The other three score contributions can distinguish the two active states via the private weights. The residual three-connected case remains open.
